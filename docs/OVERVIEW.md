# OVERVIEW — AIR (Auto AC Controller)

AIR (ชื่อทางการ "**AIR — Auto AC Controller**" ห้ามเรียก "Smart") เป็นกล่องควบคุมแอร์ห้องเรียนอัตโนมัติ: กล่องติดผนัง 1 เครื่อง/ห้อง ใช้ ESP32-S3 ตรวจจับคน (PIR/AMG8833/LD2410C), อุณหภูมิ (DHT22) และตารางเวลา (DS3231) แล้วสั่งแอร์ผ่านสัญญาณ IR โดยอัตโนมัติ พร้อมส่งสถานะขึ้น ThingsBoard Cloud ให้เว็บแอปใช้ดู/สั่งงานแอร์ได้จากทุกที่ โปรเจกต์แบ่งเป็น 3 ส่วนที่ทำงานร่วมกัน คือ **md-pcb** (ฮาร์ดแวร์/PCB), **md-firmware** (เฟิร์มแวร์ ESP32-S3) และ **md-web** (เว็บแอปควบคุม) ใช้ส่งเป็นงาน 3 วิชา (PCB/TB, CPE23367, วิศวกรรมซอฟต์แวร์) โดยมี Pream เป็นผู้ดูแลหลักฝั่งฮาร์ดแวร์/เฟิร์มแวร์/UX และเพื่อนร่วมทีมดูแลฝั่งเว็บแอป/Back-end

---

## md-pcb — ฮาร์ดแวร์ / แผ่นวงจร

**คืออะไร:** แผ่น PCB ขนาด 100×85 mm (ESP32-S3-WROOM-1U-N16R8) พร้อมเซนเซอร์ (DHT22, PIR, AMG8833, LD2410C, DS3231), จอสัมผัส ILI9341 2.8", ตัวรับ-ส่ง IR (VS1838B รับ, IR LED ×6 ยิงผ่าน Si2302), ไฟสถานะ WS2812B และ buzzer ไฟเลี้ยง USB-C 5V อย่างเดียว (ไม่มีแบตสำรอง)

**จุดเด่นด้านสถาปัตยกรรม:** ESP32-S3 อ่านเซนเซอร์ → ตัดสินใจอัตโนมัติ (ตาราง+คน+อุณหภูมิ) → ยิง IR สร้างรหัสตามยี่ห้อแอร์ (IRac) ซ้ำ 2 ครั้ง → ส่งข้อมูลผ่าน Wi-Fi/MQTT ขึ้น ThingsBoard (1 กล่อง = 1 device) → เว็บแอปอ่าน/สั่งงานต่อ ออกแบบให้ 1 กล่องคุมทั้งห้อง (IR เอียงรอบกล่อง ครอบคลุมแอร์หน้า-หลังห้อง)

**การตัดสินใจสำคัญ:** ไม่คุมไฟ 220V (ปลอดภัย), ไฟ USB-C อย่างเดียว (ตัดแบตสำรอง), เลือก ESP32-S3-WROOM-1U (เสานอกบอร์ด), Q2 ใช้ Si2302 ขับ IR หลายดวง, เพิ่ม AMG8833+LD2410C เสริม PIR (จับคนนิ่งได้), ยิงรหัส IR แบบสร้างสถานะเต็ม (ไม่ใช้ raw replay), กล่องเดียวคุมทั้งห้องแทนแยกหัว IR ติดเพดาน, เว็บต้องแสดง "ยังไม่ยืนยันสถานะแอร์จริง" เพราะ IR เป็นทางเดียว, ตัดขอบเขตเดโม (16 พ.ย.) ให้เหลือแค่ อุณหภูมิ+ตรวจคน+ยิง IR+เว็บ

**สถานะ/Roadmap:** ✅ ภาคไฟ, อัปโหลดโค้ด, ตัวรับ IR, ยิง IR สั่งแอร์ Haier ได้จริงแล้ว (HAIER_AC176) ⚠️ WS2812B ยังไม่ติด (ใส่ผิดทิศ), buzzer พัง ⏳ ยังไม่ทำ: RTC, microSD, DHT22, AMG8833, LD2410C, IR pod รอบกล่อง, จอ+ทัช, PIR, เฟิร์มแวร์รวมตัวจริง, ThingsBoard งานที่ต้องมีก่อนเดโม (สัปดาห์ 16–23 พ.ย.): DHT22, ตรวจจับคน, รวมเฟิร์มแวร์ (อัตโนมัติ+Wi-Fi+TB), ทดสอบยิง IR จริงที่ 1.5 ม. มีกำหนดส่งหลายวิชาชนกันช่วง 20–24 พ.ย. (สอบ Final Project, Infographic, วิดีโอสาธิต, เอกสารกลุ่ม)

**การเปลี่ยนแปลงล่าสุด (พ.ย. 2026):** บัดกรี/ทดสอบภาคไฟสำเร็จ, แก้ USB-C/AMS1117/MLCC ที่ช็อตจากลมร้อน, เปลี่ยน flash เป็น 16MB, ยิง IR เปิด-ปิดแอร์ Haier จริงได้สำเร็จ, วางแผนต่อสาย IR pod และเซนเซอร์เสริม, ตัดขอบเขตเดโมให้ทันส่งงาน

## md-firmware — เฟิร์มแวร์ ESP32-S3

**คืออะไร:** เฟิร์มแวร์ของกล่องควบคุม สั่งแอร์ผ่าน IR ตามคนในห้อง (PIR), อุณหภูมิ (DHT22) และตารางเวลา (DS3231) ควบคุมได้จากจอสัมผัส, Telegram, เว็บบนบอร์ด (`autoac.local`) และ ThingsBoard บันทึก log ลง microSD ข้อความ/คอมเมนต์เป็นภาษาไทยทั้งหมด

**จุดเด่นด้านสถาปัตยกรรม:** แบ่งเป็น 6 FreeRTOS task (control, ui, wifi, telegram, thingsboard, web) ทุกคำสั่งจากทุกช่องทางไหลเข้า `cmdQueue` เดียว มีแค่ **Control task** เท่านั้นที่เรียกตรรกะ `Controller` และสั่ง IR จริง (กันชนกัน) ตรรกะหลักแยกไว้ใน `lib/autoac_core` ไม่พึ่ง Arduino ทำให้เทสต์บนคอมได้ (เทสต์ native 51 เคสผ่าน) SPI ใช้ร่วมกันระหว่างจอ/ทัช/SD ต้องถือ lock เดียว มี watchdog 15 วิที่ Control task เท่านั้น

**การตัดสินใจสำคัญ:** ไฟเลี้ยง USB-C อย่างเดียว, PlatformIO+เทสต์ native, เว็บบนบอร์ดใช้ `WebServer` ไม่พึ่ง CDN, หน้าเว็บบอร์ดดูสถานะไม่ต้องรหัสแต่ตั้งค่าต้องมี `admin`, ยึด SRS+Figma เป็นหลักไม่ยึดโค้ดเดิม, เรียนรีโมต raw ก่อนแล้วจึงเพิ่ม IRac, แก้ `platformio.ini` เป็น `qio_opi` ให้ตรงบอร์ดจริง N16R8, เพิ่ม env `autoac_bench` สำหรับทดสอบไม่ต่อจอ, ปรับ timeout รับ IR เป็น 90ms, ห้าม push/commit จนกว่าผู้ใช้สั่ง (F-17)

**สถานะ/Roadmap:** ตรรกะหลักและ 6 task เสร็จและเทสต์ผ่านแล้ว บนบอร์ดจริง: ESP32-S3+WiFiManager+ThingsBoard ส่ง telemetry ได้, DS3231/microSD ผ่าน, จอแสดงโลโก้+ทัชตอบสนองแล้ว ปัญหาที่ยังแก้ไม่ได้: **PIR ค้าง HIGH ตลอด** (ไม่พบสาเหตุ), **LED5 ไม่ติด** (สงสัยเสีย) ยังไม่ต่อ DHT22/buzzer, ยังไม่ทดสอบ IR กับรีโมต Carrier จริง, ยังไม่สอบเทียบทัช นอกจากนี้มีงานค้างจำนวนมากให้ตรงตาม SRS (ช่วงอุณหภูมิแยกช่องทาง, `graceSec`, `preOpenMin`, รอบ ThingsBoard 30วิ ฯลฯ) ที่ยังไม่ทำ โปรเจกต์เลยกำหนดนำเสนอต้น พ.ย. แล้ว กำลังเร่งให้ครบของ "ต้องมีในเดโม"

**การเปลี่ยนแปลงล่าสุด (พ.ย. 2026, ยังไม่ commit):** เพิ่มหน้า `/tools`+`/api/hw` สำหรับทดสอบฮาร์ดแวร์ (LED, RTC, เรียนรู้/ทดสอบ IR), เขียน `hal/ir.cpp` จริง (Protocol+Raw), เพิ่มโลโก้ตอนบูต, แก้ `qio_opi`, ทดสอบบอร์ดจริงพบ WiFi/ThingsBoard/จอ/RTC/SD ใช้ได้แล้ว แต่ LED และ PIR ยังมีปัญหา

## md-web — เว็บแอปควบคุม

**คืออะไร:** เว็บแอป (มือถือ/เดสก์ท็อป, รองรับ PWA) สำหรับดูสถานะและสั่งแอร์จากที่ไหนก็ได้ คุยกับ **ThingsBoard Cloud (EU)** ผ่าน REST API ตรง ไม่ผ่านตัวบอร์ด เขียนเป็นไฟล์เดียว `web/index.html` (~2,400 บรรทัด) ไม่มี build step ไม่พึ่ง CDN ข้อความ UI เป็นภาษาไทยทั้งหมด ฟอนต์ Noto Sans Thai ฝังเอง

**จุดเด่นด้านสถาปัตยกรรม:** แบ่งเป็นชั้นโค้ดชัดเจน (fetch/error กลาง, ThingsBoard client, session, router แบบ hash, การแสดงผลสถานะ, ควบคุม RPC, ตาราง/ประวัติ/แจ้งเตือน) มีโหมดเดโม `?demo=1` ที่ดัก fetch จำลอง ThingsBoard ทั้งหมดโดยไม่กระทบโค้ดจริง — ลบได้ทั้งก้อน Flow หลัก: login → ดึง role/device → poll telemetry ทุก ~4 วิ → แสดงผล/สั่งงานผ่าน RPC → optimistic update รอผลจริงรอบถัดไป

**การตัดสินใจสำคัญ:** ผ่าน ThingsBoard REST เท่านั้น (ไม่คุยบอร์ดตรง), ไฟล์เดียวไม่มี build/CDN, ยึด SRS+Figma ไม่ยึดเฟิร์มแวร์, ช่วงอุณหภูมิ 16–30°C ทุก role, ห้ามแสดงสถานะแอร์แบบยืนยัน (`ok:true` = เข้าคิวแล้วเท่านั้น), สิทธิ์ Admin/User แยกที่ UI เท่านั้น (ไม่ใช่ความปลอดภัยจริง — ของจริงต้องบังคับที่ ThingsBoard/เฟิร์มแวร์), รวมหน้า "ควบคุม" เข้ากับหน้ารายละเอียดห้อง (เหลือ 4 แท็บ), ไม่ใช้ refresh token, ทำไฟล์ "AIR prototype" แยกสำหรับนำเสนอแบบไม่ต้องมีเน็ต, ห้ามแตะ GitHub (push/merge/PR) จนกว่าผู้ใช้สั่ง

**สถานะ/Roadmap:** การ redesign ตาม Figma เสร็จหลายช่วง (A/B/C) เหลือเฉพาะหน้าจัดการผู้ใช้ (ข้ามไปแล้วตามคำสั่งผู้ใช้) เชื่อมกับ Wokwi→ThingsBoard ได้แล้ว (เห็นหลายห้อง, จัดการ error ภาษาไทย) ยังค้าง: ทดสอบ login/RPC จริงแบบครบวงจร กับบอร์ดจริง, ยกเลิก hardcode `DEVICE_ID`, ชุดทดสอบอัตโนมัติ และงานที่รอฝั่งเฟิร์มแวร์/Back-end ส่งข้อมูลตามสเปกใหม่ (`graceSec`, `preOpenMin`, รอบ 30วิ ฯลฯ) มีปัญหา local/remote branch แยกทางกันที่ต้องตัดสินใจก่อน push/PR

**การเปลี่ยนแปลงล่าสุด (พ.ย. 2026, ยังไม่ commit):** ทำ "AIR prototype" ไฟล์เดียวสำหรับเดโม, อัปโปรเจกต์ขึ้น GitHub Private, จัดการ error API เป็นภาษาไทยอย่างเป็นระบบ, แก้บั๊กเลือกห้องไม่ได้ตอน login เป็น Admin

## ภาพรวมทั้งโปรเจค

ทั้งสามส่วนประกอบกันเป็นห่วงโซ่เดียว: **md-pcb** วางฮาร์ดแวร์และเซนเซอร์ให้ **md-firmware** อ่านค่าและสั่งแอร์ผ่าน IR ตามกฎอัตโนมัติ (ตรวจคน+อุณหภูมิ+ตาราง) จากนั้นเฟิร์มแวร์ส่งสถานะขึ้น ThingsBoard Cloud ซึ่งเป็นจุดเชื่อมกลาง — ให้ **md-web** อ่าน/สั่งงานกลับผ่าน REST API โดยไม่ต้องคุยกับบอร์ดโดยตรง ทำให้ดูแลและสั่งแอร์ได้จากทุกที่ ทุกส่วนยึดหลักการเดียวกัน คือ ใช้ **SRS + Figma เป็นมาตรฐาน** (ไม่ใช่ยึดโค้ดที่มีอยู่), ห้ามแสดงสถานะแอร์แบบยืนยัน (เพราะ IR เป็นทางเดียว), และห้าม push/commit ขึ้น GitHub จนกว่าผู้ใช้จะสั่งเอง

ในภาพรวมสถานะ ณ 16 พ.ย. 2026 โปรเจกต์กำลังอยู่ในช่วงเร่งสุดก่อนเดโม/สอบ: ฮาร์ดแวร์ (PCB) ยิง IR สั่งแอร์จริงได้แล้วแต่ยังขาดเซนเซอร์ตรวจคน/อุณหภูมิและไฟสถานะที่ใช้งานได้จริง เฟิร์มแวร์มีตรรกะและโครงสร้าง task ครบพร้อมเทสต์ผ่านแล้ว แต่ยังมีปัญหาฮาร์ดแวร์จริงที่ยังแก้ไม่ได้ (PIR ค้าง, LED เสีย) และยังไม่ตรงสเปก SRS หลายจุด เว็บแอปพัฒนาหน้าตาตาม Figma เสร็จเกือบหมดแล้วและเชื่อมกับ ThingsBoard ได้ แต่ยังรอทดสอบกับบอร์ดจริงแบบครบวงจรและรอให้เฟิร์มแวร์ส่งข้อมูลตามสเปกที่ตรงกัน จุดร่วมที่ทั้งสามส่วนรอคอยคือ "เฟิร์มแวร์ตัวจริงบนบอร์ดที่ใช้งานได้ครบ" ซึ่งเป็นงานที่เหลือมากที่สุดและเป็นคอขวดของเดโมที่จะมาถึง (กำหนดส่งงาน 3 วิชาชนกันช่วง 17–24 พ.ย. 2026)
